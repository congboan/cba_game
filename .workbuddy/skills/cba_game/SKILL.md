# cba_game

## 三层架构

本项目采用 Lyra 风格的三层开发架构：

| 层 | 位置 | 放什么 |
|---|---|---|
| Framework Plugins | `Plugins/<name>/`（非 GameFeatures） | 可复用的纯能力机制。技能框架、背包框架、交互系统——不包含具体游戏内容 |
| Project Base | `Source/cba_game/` + `Content/` | 项目级共享。所有 GF 都可能用到的：全局 GameplayTag、基础控件、通用美术资产、项目基类 |
| GameFeatures | `Plugins/GameFeatures/<name>/` | 游戏本身。一个 GF = 一个完整的游戏体验。有自己的 Source/、Content/，可以依赖 Framework 和 Project Base |

### 决策树

想加一段代码或资产时，按顺序判断：

1. 这个能力能独立拆出来给另一个项目用吗？
   - 能 → Framework Plugin（`Plugins/<name>/`）
   - 不能 → 继续
2. 这个东西是所有 GF 都需要的吗？
   - 是 → Project Base（`Source/cba_game/` 或 `Content/`）
   - 不是 → GameFeature（`Plugins/GameFeatures/<name>/`）

### 硬约束（机械门禁）

- **GF 位置**：包含 `BuiltInInitialFeatureState` 或 `ExplicitlyLoaded: true` 的 `.uplugin` 必须放在 `Plugins/GameFeatures/<name>/` 下。由 `check_gf_location.py` 强制执行。
- **依赖方向**：Framework Plugin（`Plugins/<name>/`，非 GameFeatures）不能依赖 GameFeature Plugin。由 `check_gf_dependency.py` 强制执行。
- **描述符证据**：`.uplugin` 修改必须向门禁提供修改后的完整 JSON；只携带局部替换文本的 Edit 无法证明最终描述符，会只拒绝当前调用并要求改用完整文件写入。删除操作不受此限制，以便移除违规描述符。
- **资产文件**：`.uasset` / `.umap` 是 UE 二进制资产包。任何被 Harness 识别为资产变更的调用都必须由当前有效 provider 提供 `ue.asset.edit` capability；普通文件工具不具备该能力。由 `project.asset.uasset-editor-capability` + `project.asset.umap-editor-capability` 强制执行。
- **Shell 资产操作**：禁止通过 Bash/PowerShell 对 `.uasset` / `.umap` 执行写入类操作（copy、move、delete 等）。由 `project.asset.shell-write` 强制执行。
- **Include 纪律**：每个 `.cpp` 文件中的 `#include "*.generated.h"` 必须是最后一条 `#include`，否则 UHT 静默吞掉反射数据。由 `check_generated_include.py` 强制执行。
- **UE 命名前缀**：`UCLASS` 的类名必须以 `U` 或 `A` 开头，`USTRUCT` 以 `F`，`UENUM` 以 `E`。由 `check_ue_naming.py` 强制执行。

### 认知约束（AI 自觉遵守，非机械门禁）

- "这段 C++ 是胶水还是玩法逻辑" — 语义判断，无法机械化
- "这个资产是不是所有 GF 都要用" — 人的设计决策
- 当 `Plugins/GameFeatures/` 目录不存在时，依赖方向检查自动跳过（无 GF 则无违规）
- Root skill 已按工具范围声明 `tool_providers`（`mcp__ue5__*` → `ue.asset.edit`），不绑定单个工具名或猜测 payload 字段。AI 需要修改资产时，用 ToolSearch 确认 `mcp__ue5__*` 工具在当前会话可用；MCP 未运行或工具不可用时，引导用户在 UE Editor 中操作
- Shell 命令**禁止使用复合语法**（`&&`、`|`、`>`、`<`、`;`、`$()`、反引号等）。harness 的 `operation_normalizer` 已机械拦截复合命令，将其标记为 unresolved 并拒绝当前调用。需要串联多个命令时拆成多次独立的 Bash/PowerShell 调用

## Experience Framework 工作流

ExperienceFramework (`Plugins/ExperienceFramework/`) 是从 Lyra 提取的 Experience/GameMode 驱动机制。它是一个纯 Framework Plugin，不包含任何具体游戏内容。核心概念：用 `UExperienceDefinition` 数据资产声明「这场游戏是什么」。

### 核心数据资产

**UExperienceDefinition** (PrimaryDataAsset) — 游戏的「定义文件」

```
GameFeaturesToEnable  → 激活哪些 GF 插件（插件名称列表）
DefaultPawnData       → UExperiencePawnData 引用
Actions               → 内联 UGameFeatureAction 实例
ActionSets            → UExperienceActionSet 引用（可复用 Action 包）
```

**UExperienceActionSet** (PrimaryDataAsset) — 可复用的 Action 包，多个 Experience 共享同一套 Action 组合（如标准 HUD + 基础输入绑定）

```
Actions               → 内联 UGameFeatureAction 实例
GameFeaturesToEnable  → 可选 GF 依赖
```

**UExperiencePawnData** (PrimaryDataAsset) — Pawn 配置

```
PawnClass             → 生成哪个 Pawn
AbilitySets           → UExperienceAbilitySet 引用列表
TagRelationshipMapping → 技能 Tag 关联规则
InputConfig           → 默认 EnhancedInput 配置
```

### 加载状态机

`UExperienceManagerComponent`（挂载在 GameState 上）驱动六态生命周期：

```
Unloaded → Loading → LoadingGameFeatures → ExecutingActions → Loaded → Deactivating
```

- `SetCurrentExperience(FPrimaryAssetId)` 由 Server 调用；`CurrentExperience` 是 Replicated 属性，客户端通过 `OnRep_CurrentExperience()` 启动本地加载，不是 RPC
- **LoadingGameFeatures**：激活 ExperienceDefinition + ActionSet 中声明的所有 GF 插件
- **ExecutingActions**：执行所有 GameFeatureAction（内联 + 来自 ActionSet）
- **Loaded**：广播 `OnExperienceLoaded`，触发 Pawn 生成等后续流程
- **Deactivating**：当前实现只在 `EndPlay()` 中进入；先请求停用已记录的 GF 插件，再按声明顺序对内联 Actions 和各 ActionSet Actions 调用 `OnGameFeatureDeactivating()` / `OnGameFeatureUnregistering()`，不得假设逆序

### Pawn 初始化

`UExperiencePawnExtensionComponent`（挂载在 Pawn 上，实现 `IGameFrameworkInitStateInterface`）推进四态：

```
Spawned → DataAvailable → DataInitialized → GameplayReady
              │
         PawnData 就位
```

- `PawnData` 由 GameMode 从 `ExperienceDefinition.DefaultPawnData` 获取并设置
- 该组件负责保存并复制 `PawnData`、协调 InitState，以及提供 `InitializeAbilitySystem()` / `UninitializeAbilitySystem()` 扩展点
- 当前实现的 `HandleChangeInitState()` 为空，状态推进本身不会自动初始化 ASC
- 当前实现的 `SetupPlayerInputComponent()` 只重新检查初始化状态，不会自动应用 `PawnData.InputConfig`；具体 ASC 与输入接线必须由 Pawn/PlayerState/Controller 集成层完成

### GameFeatureAction 体系

基类 `UExperienceGameFeatureAction_WorldActionBase` 简化了 UE 原始 `UGameFeatureAction`。直接覆写一个纯虚函数，基类自动处理多 World 分发和 delegate 注册：

```cpp
virtual void AddToWorld(const FWorldContext& WorldContext,
                        const FGameFeatureStateChangeContext& ChangeContext) PURE_VIRTUAL;
```

五位具体 Action：

| Action | DisplayName | 功能 |
|---|---|---|
| `UExperienceGameFeatureAction_AddAbilities` | Add Abilities | 按 ActorClass 匹配 → 授予 GA / AttributeSet / AbilitySet |
| `UExperienceGameFeatureAction_AddWidgets` | Add Widgets | 往 HUD 推 UIExtension 的 Layout + Widget (`CommonActivatableWidget`) |
| `UExperienceGameFeatureAction_AddInputContextMapping` | Add Input Mapping | 注册 EnhancedInput MappingContext，带 Priority |
| `UExperienceGameFeatureAction_AddGameplayCuePath` | Add Gameplay Cue Path | 声明相对插件 Content 的 GameplayCue 目录；由 `UExperienceGameFeature_AddGameplayCuePaths` 策略观察者在 GF 注册/注销时应用 |
| `UExperienceGameFeatureAction_SplitscreenConfig` | — | 配置分屏参数 |

### 关键类关系

```
AExperienceGameMode (extends AModularGameMode)
│  └── InitGame → 选 Experience → ExperienceManagerComponent
│  └── GetDefaultPawnClassForController → 从 PawnData.PawnClass 取
│
AExperienceGameState
│  └── UExperienceManagerComponent (= 核心状态机)
│        ├── SetCurrentExperience(FPrimaryAssetId)
│        └── CurrentExperience (Replicated)
│
APawn
│  └── UExperiencePawnExtensionComponent
│        ├── PawnData (Replicated)
│        ├── ASC 初始化和反初始化
│        └── InitState 推进（Spawned → DataAvailable → DataInitialized → GameplayReady）
│
UExperienceManager (EngineSubsystem)
   └── 引用计数：NotifyOfPluginActivation / RequestToDeactivatePlugin
```

### 依赖

ExperienceFramework 的 `.uplugin` / Runtime Module 依赖包括：`GameFeatures`、`GameplayAbilities`、`EnhancedInput`、`ModularGameplay`、`ModularGameplayActors`、`CommonUI`、`CommonGame`、`UIExtension`。这些是 UE 或项目插件/模块依赖，不等同于本项目三层架构中的 Framework Plugin 分类。

它不依赖任何 GameFeature Plugin。`project.arch.gf-dependency` 门禁会持续守住这个底线。

### 操作流程

#### 触发场景

以下任务需要涉及 ExperienceFramework：

- 新建一个游戏模式/关卡 → 创建对应的 `UExperienceDefinition`
- 给已有 Experience 增减 GameFeatureAction
- 新建 GF 插件 → 在对应 Experience 的 `GameFeaturesToEnable` 中登记
- 调整 Pawn 配置（技能、输入、属性）
- 抽取可复用的 Action 组合 → 创建 `UExperienceActionSet`

#### 创建新 Experience

按顺序：

1. **创建 `UExperienceDefinition` 数据资产**（放在对应 GF 或 Project Base 的 Content 目录）
2. **（如果需要）创建 `UExperiencePawnData`** — 指定 PawnClass、AbilitySets、InputConfig
3. **（如果需要）创建 `UExperienceActionSet`** — 把可复用的 Action 组合抽取出来
4. **配置 `GameFeaturesToEnable`** — 列出此 Experience 需要的 GF 插件名称（如 `ShooterCore`）；运行时通过 `GetPluginURLByName()` 解析 URL
5. **添加 `Actions`**（内联 Action）和 `ActionSets`（引用） — 按加载顺序排列
6. **选择 Experience** — 可配置 `ExperienceDeveloperSettings.DefaultExperience`；PIE 可使用 `ExperienceOverride`。启动选项 `?Experience=<PrimaryAssetName>` 接收资产名，命令行 `-Experience=<Type:Name|Name>` 接收 PrimaryAssetId 或资产名；WorldSettings 也可提供默认值
7. **验证**：启动关卡 → 通过 `IsExperienceLoaded()` / loading-screen 状态确认加载完成；需要检查私有 `LoadState` 时使用调试器或临时日志

修改 Action 或 GF 列表后，已有运行中的 Experience 不会热更新；需要重启关卡。

#### 修改已有 Experience

1. 找到目标 `UExperienceDefinition` 资产（路径通常在对应 GF 或 Project Base 的 Content 下）
2. 修改字段后**不需要改 C++ 代码** — 所有配置都是数据驱动的
3. 如果增减了 `GameFeaturesToEnable`，确认对应的 GF 插件存在于 `Plugins/GameFeatures/` 下
4. 如果修改了 `Actions` / `ActionSets`，注意执行顺序：内联 Actions 先于 ActionSet 内的 Actions

#### 新建 GameFeatureAction

当五位内置 Action 不满足需求时：

1. 需要按 World 安装能力时，继承 `UExperienceGameFeatureAction_WorldActionBase`；不需要 World 分发的 Action 可直接继承 `UGameFeatureAction`
2. 使用 WorldActionBase 时覆写 `AddToWorld()`，由基类处理多 World 分发和 GameInstance delegate
3. 如需额外反激活逻辑，覆写 `OnGameFeatureDeactivating()` 并保留基类清理
4. Action 类可以放在 Framework Plugin（通用能力）或 GF（玩法专属），取决于复用需求
5. 在 `ExperienceDefinition` 或 `ActionSet` 的 `Actions` 数组中实例化

#### 验证

- **编辑器内**：`UExperienceDefinition` 有 `IsDataValid()` 校验，保存时自动检查
- **运行时**：优先检查 `IsExperienceLoaded()` 与 loading-screen 状态；私有 `LoadState` 只通过调试器或临时日志观察
- **Pawn 侧**：确认 `UExperiencePawnExtensionComponent::PawnData` 已 Replicate 且 InitState 到达 `GameplayReady`
- **GF 引用计数**：`GameFeaturePluginRequestCountMap` 是私有静态状态，需要通过调试器或临时日志验证正确增减

## Autonomous Development Pipeline

用户给出需求后，AI 自主完成规划→编码→编译→审查→修复的全闭环，直到代码满足规范才交付。中间不需要人工介入。

### 流水线架构

```
Human: "Add X feature"
    │
    ├─ [Planner] AI 自主规划
    │     ├─ 分析需求，确认 Spec 范围
    │     ├─ 三层决策：代码放 Framework / Project Base / GameFeature
    │     └─ 拆解为可并行/串行的子任务
    │
    ├─ [Coder] 编码（子任务可各自并行）
    │     ├─ 写代码（16 条 harness 约束实时拦截）
    │     ├─ 编译（PostToolUse UBT 自动触发）
    │     └─ 编译失败 → 分析错误 → 修正 → 重编
    │
    ├─ [Reviewer] 审查
    │     ├─ 按 Code Review Checklist 逐项检查
    │     ├─ 输出问题清单（分级：blocker / style / suggestion）
    │     └─ blocker 未清 → 打回 Coder → 回到上一步
    │
    └─ [Loop] 编码↔审查 迭代
          ├─ 不设迭代次数上限
          ├─ 审查不再产出新 blocker → 通过
          └─ 交付：代码 + 编译通过证明 + 最终审查报告
```

### Agent 角色

Coder 和 Reviewer 是独立 Agent——消除自审盲区。AI 按阶段按需 spawn：

| Agent | 类型 | 权限 | 触发时机 | 职责 |
|---|---|---|---|---|
| **Planner** | general-purpose | 读写 | 接到新需求时 | 拆解任务、确定放置位置、编写 spec |
| **Coder** | general-purpose | 读写 | 具体子任务执行 | 编码 + 编译 + 修复编译错误。大任务可 spawn 多个并行 Coder |
| **Reviewer** | Explore（只读） | **只读** | 编码完成一批文件后 | 按 Checklist 审查，产出结构化问题清单。**不能写代码，不能顺手修** |
| **Explorer** | Explore | 只读 | 需要查接口/规���时 | 跨文件搜索、API 查询、代码分析 |

**边界规则**：
- Reviewer **禁止**写代码。发现问题只能记录并返回给 AI 主控，由主控判断是否打回 Coder
- Coder 收到 Reviewer 问题清单后逐条修，重修完毕 → 主控再次 spawn Reviewer 审
- 一个 Coder 审另一个 Coder 的代码（不是自己审自己），消除作者盲区

**自循环规则**：
- Coder ↔ Reviewer 循环由 AI 自主驱动，直到 reviewer 全部绿灯
- 审查问题分三级：
  - **Blocker**：必须修，否则不能交付（架构错误、安全漏洞、harness 命中）
  - **Style**：应修，但不阻止交付（代码不优雅、重复逻辑）
  - **Suggestion**：建议修，酌情处理
- Blocker 全清 + Style 处理完毕 → 交付
- Suggestion 可留给用户后续参考，不阻塞交付

### 安全网

AI 完全自主运作，但以下防线永不降权：

- **16 条 harness 约束**：每次 pre_write 强制执行，拦截结构性错误
- **build_freshness**：stop/commit 前验证源码编译新鲜度
- **资产保护**：`.uasset`/`.umap` 必须经 ue5 MCP
- **post-compile 验证**：UBT 失败自动回环修复

AI 有航行自由，航道两侧是防撞墙。

## Code Review Checklist

Reviewer Agent 的审查依据。标注 [H] 的项目已被 harness 硬拦截，但 Reviewer 仍要验证——若命中则说明上游 Coder 未正确处理 harness deny。

### 编译与结构

- [H] `.generated.h` 是 `.cpp` 中最后一条 `#include`
- [H] UE 命名前缀（U/A/F/E）正确
- [H] 无硬编码引擎路径
- [H] `.uplugin` 位置正确、依赖方向合法
- [ ] `.Build.cs` 依赖与实际 `#include` 匹配（public/private 分离）
- [ ] 无 `UPROPERTY()` 空括号
- [ ] 单文件单主类，无上帝类
- [ ] 编译通过（UBT 无 error；warning 酌情）

### 三层架构

- [ ] 新代码放置符合三层决策树
- [ ] GF 代码未混入 Framework Plugin
- [ ] Framework Plugin 未引入具体游戏内容
- [ ] 新建 GF 时 Experience 的 `GameFeaturesToEnable` 已登记

### GAS

- [ ] Ability 逻辑在 `UGameplayAbility` 子类，不散落在 Character/Controller
- [ ] `AttributeSet` 不持有 World 引用（pre-net-replication 时可能无效）
- [ ] `GameplayEffect` modifier 不超过 3 层
- [ ] ASC 初始化时机正确（通过 `PawnExtensionComponent` 扩展点接入）

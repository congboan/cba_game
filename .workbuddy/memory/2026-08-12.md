## build_freshness stop 门禁优化（A+B 方案，用户提出）

- **问题**：stop 触发 build_freshness 跨会话卡人——纯问答 session（无代码写入）继承历史坏指纹也 deny；PostToolUse 自动编译的环境性失败（UBA/编辑器锁）覆盖成功指纹 → 死循环。
- **方案 A（会话标记）**：`Saved/harness_session_codemodified.json`。SessionStart（--context）清标记 → evaluate() pre_write 命中代码路径（Source/**、Plugins/** 的 .h/.cpp/.cs）置标记 → `_eval_build_freshness` 在 event==stop 且无标记时 return None（跳过）。
- **方案 B（指纹保留）**：build_editor.py `_preserve_success_state(fp)`——源码与上次成功编译一致时保留成功指纹（不写 running/failed），环境性失败不破坏门禁；早期失败路径（uprojects/engine）也尊重 preserve。启动 invalidate 移到 fp_before 之后（原 starting invalidate 会先销毁指纹，是实施中发现的 bug）。
- **验证**：无标记 stop 放行 ✓、有标记走检查（指纹有效通过）✓、--context 清标记 ✓、编译输出 `[INFO] Source unchanged; previous success preserved` ✓。
- 治理任务走 governance-authoring 完成，selector 已恢复 settings-ui-framework。

## stop 门禁边界修复（方案 1：清标记只绑定 SessionStart）

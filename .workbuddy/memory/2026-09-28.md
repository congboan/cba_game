## Why type erasure at all (design rationale, user asked)
- Rule derived from the code: erase at the BOUNDARY, never in the interior. Three competing constraints force it:
  1. UHT/replication: FNetworkPredictionProxy must be a non-template USTRUCT with NetSerialize and a UPROPERTY(Replicated, transient) member (NetworkPredictionComponent.h:59-60, DOREPLIFETIME :66-69); a template proxy / template UCLASS is not processable by UHT -> infeasible by construction
  2. Performance: hot path needs compile-time typed, by-value layout (TConditionalState embeds State, ConditionalState.h:26) so per-frame compare/restore/resim stays inlineable; full void* + runtime type dispatch would regress the frame loop
  3. Extensibility: ModelDef is user-defined; engine cannot pre-instantiate virtuals for unknown user types -> static-init registry assigns small integer IDs (ModelDefRegistry.h:12-59)
- Erasure appears in exactly three places, at graded depth: proxy (ID + View + ConfigFunc + CachedConfig), service interfaces (services only touch FNetworkPredictionID, ServiceRegistry.h:46), everything inside TModelDataStore<ModelDef>/frame buffers/DoTick stays strongly typed
- The three mechanisms that keep erased code functional: (a) ID化 - ModelDef::ID as service-array index (ModelDefRegistry.h:10-11); (b) 索引化 - InstanceIdx/FramesIdx (NetworkPredictionInstanceData.h:106-107) so services walk bit arrays (Rollback.inl:77, :166); (c) 回调化 - ConfigFunc TFunction + EConfigAction enum (Proxy.h:269, :246-256). Reads need none of it (caller supplies the type, Proxy.h:101-154)
- Cost of erasure: static_cast correctness is on the caller (base GetScriptStruct() is checkf(false), MoverTypes.cpp:63-67); templates instantiate for all ModelDefs regardless of compatibility (ServiceRegistry.h:62-69); runtime type info is reduced to an int, needs registry lookup for debugging
- Contrast with Mover's inner layer: FMoverDataCollection IS a partial erasure (runtime UScriptStruct key) because it must support dynamic composition (users add blocks); NP's frame buffer is a fixed triple so it stays fully typed. Rule of thumb: erase only where polymorphism/UHT boundary requires it, and let the need for dynamic composition decide the granularity

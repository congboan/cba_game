## 项目 MCP 审计（只读诊断，未修改任何治理源）

### 配置事实
- 客户端 `~/.workbuddy/mcp.json`：仅 1 个 server `ue5`（streamable-http，`http://localhost:8000/mcp`，未 disabled）。
- 治理侧 root skill 声明 1 个 provider `ue5-editor-mcp`：`tool_glob: mcp__ue5__*`、`capabilities: [ue.asset.edit]`、`requirements: 0`；effects = pre_tool(partial) + pre_write(write, `path_field: arguments.AssetPath`, exact)；`unresolved_events: [pre_tool]`。
- 运行时：Editor 在线，`list_toolsets` 返回 60+ toolset，含本项目自研 `SettingsFrameworkEditor.SettingsFrameworkToolset`。

### 发现的覆盖缺口（P1）
provider 声明的 `path_field: arguments.AssetPath` 与真实 MCP 工具参数命名**不匹配**，且三种命名风格并存：
- Python toolset（`editor_toolset.*`）：snake_case — `asset_path` / `file_path` / `path` / `new_path` / `asset_paths`
- C++ toolset（`SettingsFrameworkEditor.*`、`UMGToolSet` 等）：camelCase — `assetPath`
- root skill 声明：PascalCase — `AssetPath`（三者无一命中）

链路后果：`operation_normalizer._provider_effect_requests` 在字段缺失时执行 `if not values: continue`（静默跳过该 effect）→ MCP 调用**永不产生 pre_write evaluation request** → 所有 `when: pre_write` 约束对 MCP 写入全部失效：`.uasset`/`.umap` capability 门禁、`path_writable_stage`、`check_spec_required`、`check_generated_include`、`check_ue_naming`、gf-location/dependency、引擎只读、`authoring-required`。
且全部 18 条约束中**无一条 `when: pre_tool`**，故 provider 的 `unresolved_events: [pre_tool]` 在 `_unresolved_event_blockers` 中找不到 blocker → abstain 放行。
结论：MCP（含 `AssetTools.write_file` / `delete` / `move`）是当前唯一完全不受路径、阶段、spec 范围约束的写入通道。

### 待决策
provider schema 的 effect 只允许**单条** `path_field`，无法表达候选字段名列表 —— 这是机制层限制，修法需用户在治理任务中定夺（改声明 / 加 `when: pre_tool` 兜底 / 扩展 effect schema 支持候选字段或按 toolset 分 provider）。修改 root skill 属治理任务，需 `governance-authoring` 且写入 `.workbuddy/skills` 逐次人工确认。

## 更正：不是缺口，是设计（用户当日校准）

治理层设计即「`.uasset` 只能经 MCP 改，不能经 shell」。授权闭环自洽：

- shell 改 `.uasset` → `project.asset.shell-write`(pre_command) 拒绝
- Write/Edit 改 `.uasset` → `uasset-editor-capability`(pre_write + require `ue.asset.edit`) 拒绝（无 provider 提供该 capability）
- MCP 改 `.uasset` → 走 pre_tool 放行（受信写入口）

故 `path_field` 不命中的唯一后果是「不对 MCP 做路径级审计」，符合设计意图；`ue.asset.edit` 在该设计里是**纯拒绝用**能力（`required_tool_capabilities` 为空）。

## 引擎源码第一手事实（`D:\UnrealEngine`，UE 源码构建）

- 插件 `Engine/Plugins/Experimental/ModelContextProtocol`：FriendlyName "Unreal MCP"，NoRedist / Experimental / EnabledByDefault=false；依赖 `EngineAssetDefinitions` + `ToolsetRegistry`
- Tool Search 默认开启 → `tools/list` 只返回引擎硬编码的三元工具 `list_toolsets` / `describe_toolset` / `call_tool`
- `call_tool` schema：`toolset_name`（可选）/ `tool_name`（必填，不带 toolset 前缀）/ `arguments`（对象，默认 `{}`）
- **引擎无授权层**：`IModelContextProtocolModule` 只有 AddTool/RemoveTool/StartServer 等；`UToolsetDefinition` 只有 `IsFunctionAICallable`（AICallable / AIIgnore 二元；非 static 或缺标注会报错）
- 工具集全名 = `<模块名>.<类名>`；实测注册 **70 个** toolset
- 参数命名：C++ UFUNCTION 经 `FJsonObjectConverter::StandardizeCase` → PascalCase 变 camelCase；Python toolset（`@toolset_registry.tool_call`）保留 snake_case

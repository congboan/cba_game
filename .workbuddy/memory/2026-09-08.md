- 上移：5 个硬编码 native tag 绑定到路由策略层（捕获/路由/消费三层），第一阶段只落 AvatarRouter（接口中立，默认实现），RTS/载具 GF 立项时再注册新 Router。

## 全 GA 输入方案（用户拍板方向：不用 native input）
- 形状：EnhancedInput 捕获 → InputEventRouter 桥接（PlayerController/PlayerState 侧，IA 事件组 FGameplayEventData + InstancedEventData 传 FInputActionValue）→ SendGameplayEventToActor → 全部 GA 消费。
- 两种 GA 模式分工：每帧 axis（move/look）= InstancedPerActor 常驻 GA（TryActivateAbilitiesOnSpawn 自动激活）+ WaitGameplayEvent 精确订阅，值写中立 avatar 输入状态组件，Mover producer/相机桥从那读；离散动作 = GameplayEvent trigger 走正常激活管线。
- 网络事实：LocalPredicted 离散 GA 服务端 CurrentEventData 为空（EventData 不随激活复制），需 payload 的服务端逻辑走 TargetData RPC（Lyra 射击同款）；axis GA 纯本地+Mover input replay，无复制需求。
- 三条纪律：axis GA 禁用 trigger 模式（已激活事件被 InternalTryActivateAbility 丢弃）；InputTag.* 全域禁配 AbilityTriggers（GiveAbility 即注册，父链冒泡会误触）；axis 事件 tag 独立命名空间。
- 核心增值：输入消费 100% GA 资产化，与 AAF JSON 动态 GA 直接对口；路由层单一接口。代价：每帧事件分发+payload 拷贝（噪音级）、调试面从 C++ 绑定变事件流、常驻 GA 挂满 ASC。
- 落点：Router 桥接在 ExperienceFramework，GA 基类/约定在 AAF；待立 spec。

## 方案收敛：不做中间件，全走 BindAbilityActions（用户最终意图）
- 用户拍板：HeroComponent 删全部 BindNativeAction，move/look/crouch/autorun 的 IA 全进 InputConfig.AbilityInputActions，统一走 BindAbilityActions → Input_AbilityInputTagPressed/Released → ASC->AbilityInputTagPressed/Released 现有链路。不造 Router。
- 唯一缺口 = 值通道：BindAbilityActions 委托只传 tag（LyraInputComponent.h:63），Input_AbilityInputTagPressed(FGameplayTag) 签名无值。
- 三选项：A = LyraASC 扩展 AbilityInputTagPressed(Tag, Value) + tag-to-value 缓存，axis GA 每 tick 查询（推荐，贴合 ProcessAbilityInput 批处理架构）；B = ASC 内部组 EventData 走 HandleGameplayEvent（绕回事件通道）；C = GA 自查 EnhancedInputComponent.GetBoundActionValue（零 GAS 改动但取值链长、GA 要配 IA 引用）。
- tick 语义：Triggered 每帧触发 → AbilityInputTagPressed 每帧 AddUnique 进 InputPressedSpecHandles → ProcessAbilityInput 每帧一次 InputPressed 事件 → Clear。axis GA 应常驻激活 + 查询值，不监听每帧 Pressed 事件（避免 InvokeReplicatedEvent 复制成本，LyraASC:163 注释确认仅监听才复制）。
- crouch/autorun toggle 型零值需求，直接 GA 化免费。真正要补值的只有 move/look。

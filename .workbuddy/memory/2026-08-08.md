## git pull 后 Stop 门禁（build_freshness）拦截的修复

- 现象：git pull（d184d20..0a00c5b，49 文件）后 Stop 报 `[HARNESS] no successful build matching current source`，build_editor.py 报 `[SKIP] Engine root not found`。
- **根因**：`cba_game.uproject` 的 `EngineAssociation` 是 `{18279027-48C0-92CB-E808-08A378516D1D}`，该 GUID 在本机注册表中不存在（d184d20 提交误改回无效 GUID；825ffe4 曾正确改为 `{21868A7F-...}`）。新版 `resolve_engine.py` 复刻 UnrealVersionSelector、删除"唯一候选回退"，精确匹配失败即返回 `association_not_registered`，环境变量 `ENGINE_ROOT` 也未设置，故无法解析引擎。
- **修复**：将 uproject EngineAssociation 改回本机实际注册的 5.9 源码引擎 GUID `{21868A7F-44F6-431E-75F4-908AD7D3F93D}`（→ E:\UnrealEngine, 5.9.0），resolve_engine 恢复解析，重跑 build_editor.py 刷新指纹。
- 经验：
  1. 手动调用 harness 脚本必须用 `envs/default` 的 python（装有 PyYAML）；托管主环境和系统 Python 都没有 yaml。
  2. `git pull` 直接用纯命令（normalizer 的 `GIT_NON_WORKTREE_SUBCOMMANDS` 含 pull），不要用 `git -C` 形式。
  3. 引擎解析：Target.cs 锁 Unreal5_9 → 必须用 5.9 引擎；uproject EngineAssociation 必须匹配本机注册的 GUID。
